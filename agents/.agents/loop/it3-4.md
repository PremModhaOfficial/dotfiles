## 1. The shape: one anchored activation grammar, end characters enumerated

A token is exactly `<open> / <name> <end>`, and only that:

- **open**: start of line, space, tab, or one opening quote/backtick (`"` `'` `` ` ``).
  Nothing else. A path character before the slash (`a/`, `./`, `~/`, `</`, `=/`)
  fails the assertion, so the rewriter never reaches inside a path.
- **end**: end of line, space, tab, comma, colon, semicolon, period, closing
  paren `)`, closing quote `"` `'`, closing backtick. Nothing else is accepted.
- **boundary guard on the separators** (comma, colon, semicolon, period): such a
  character only ends the token when it is itself followed by end of line, a
  space, a tab, or a closing quote/paren/backtick. This is what kills `/brag.md`,
  `/brag;param`, `/brag,x` **without writing a single exclusion**: the period in
  `.md` is not followed by an end character, so the grammar has no match at all,
  the line is returned byte-identical, and the rewriter never sees a substring.

The regex, in full, has no negated class anywhere:

```
(?:^|(?<=[ \t"'`])) / (?P<name>[a-z][a-z0-9]*(?:-[a-z0-9]+)*)
(?P<end> $ |[ \t] |[)"'] |` |[,;:](?=$|[ \t)"'`]) |\.(?=$|[ \t)"'`]) )
```

`normalize()` is applied per line (`split("\n")`, `join`), so a line the grammar
does not match is not touched at all, down to its bytes. There is no "is this a
path?" test left anywhere, so there is nothing left to share a blind spot with.

Not special-cased, deliberately: fenced blocks. 21 tokens live inside fences and
are prose on this host (`workmux send agent-a "/skill:merge"`), so fence state is
not consulted; the token grammar alone decides.

## 2. The lint is independent, and disagreement refuses

`skills-lint.py` shares no code with the matcher and imports nothing from it. It
restates the spec and scans characters by hand:

- `expect_line(orig, names)` — its own rewrite of a line.
- `check_change(orig, new, names)` — the changed line must equal the lint's own
  rewrite, and every rewritten token keeps the same skill name and is followed
  only by a named end character.
- `tree_assert(text)` — separate output assertion over every file: no `/skill:`
  token is followed by `@ ? # * [ { /`, none is preceded by a path character,
  and every one is in prose position with a named end character.

`skills-activation.py` runs **both** over the entire post-write tree before the
first byte is written. Any disagreement or any violation prints
`REFUSED: N problem(s) in the whole-tree scan; nothing written`, exit 1.

Both self-checks are also run before every invocation, so a future edit that
widens either one fails the run instead of reporting clean.

## 7. What I could not make safe

1. **`cd /brag`** — the token is identical to a command token. Prose position
   cannot separate an absolute path argument from an activation without a
   negative rule, which is exactly what this round removed. Pinned in the table
   as a known outcome (it rewrites). No such line exists in the tree; `rg` shows
   every bare token in the wiped tree was a command.
2. **A parenthesised activation with no preceding space, `(/brag)`** — not
   rewritten, because `(` is not an opener (it is a markdown link-target
   direction). Failure mode is a bare token → exit 1, never a corrupt path.
3. **A closing quote/backtick followed immediately by letters, `"/brag"x`** —
   accepted; the closer ends the token and what follows is outside it. No such
   line exists.
4. **Bare tokens in `README.md`/`CHANGELOG.md` and in nested distribution
   checkouts** — outside the 145-file loadable tree by root glob. Pi does not load
   them. If pi's loader ever widens, the floor and the root glob are the two
   places to change.
5. The separator guard is stricter than the spec's flat list: `/brag;` or
   `/brag,` followed immediately by a word stays bare (red run) rather than
   becoming `;param`. Red is the safe direction; the spec's own list would have
   rewritten it.
