# IT3-7, round 3, attempt 7 — the job shrinks to four positions

Verdict: **implemented and measured, with the claim narrowed exactly as asked.**
The rewrite now touches only four enumerated positions where a card names a
command (line start, a list/heading marker, a `Trigger:`/`Use when:`/`Use
for:`/`Activate:`/`Invoke:` label, a whole-name code span). Everything else is
left byte-identical, and every slash character in every scanned card lands in
exactly one counted bucket. On the live tree: **0 bare in a safe position, 2781
left tokens each with a reason, bucket sum 3015 = 3015 slashes**, two real syncs
byte-identical over 9681 files (README included), all four gates green.

The claim is no longer "no bare command anywhere". It is: zero bare commands in
P1-P4, and every token left outside them counted by reason. That change is
forced by the rule, and it shows on the live tree: 17 cards that a sync
re-copies from upstream now keep prose forms like ``(alias `/caveman ultra`)``
and `/caveman status` bare, because those are not one of the four positions.
They are counted (`position=49`), not silently dropped, and not refused.

## 1. The rule, as code

`jcode/skill_slash.py` — one function per question, no neighbouring-word guess
and no command list:

| position | test in code | example |
|---|---|---|
| P1 line start | everything before the slash is blanks | `  /brag --tone chaotic` |
| P2 marker | `^[ \t]*(?:[-*+]\|#{1,6}\|\d{1,9}[.)])[ \t]+$` ends at the slash | `- /brag`, `### /brag`, `12) /brag` |
| P3 label | the word(s) before the colon are `trigger`/`use when`/`use for`/`activate`/`invoke`, blanks free | `Trigger:/brag`, `Trigger: /brag` |
| P4 code span | one single backtick, content exactly `/name`, one backtick | `` `/brag` `` |

A candidate is `/` + exactly an installed name, not continued by another name
character (`/bragx`, `/brag-`, `/brag_x` are not `brag`), and the character
after the name must end the token: end of line, blank, `)`, `"`, `'`, backtick,
or `,` `;` `:` `.` `!` `?` `|` `*` followed by a boundary. That tail rule is
what keeps `/brag.md`, `/brag/x`, `/brag@2x.png`, `/brag{x,y}`, `/brag?tab=x`
and `/brag,:` whole with no path reasoning at all.

Deletions that made the code smaller: `PATH_CHARS`, `PATH_COMMANDS`,
`BRACKET_OPEN`, `COMMAND_LOOKBACK`, `words_before()`, `block_reason()`, the
`END`/`OPEN` regexes. One parser (`buckets()`), two consumers
(`rewrite_line()`, `scan()`), one independent checker.
