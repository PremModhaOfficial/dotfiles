## 1. The opener set, and what happens to a mid-line mention

A token is `<open> "/" <name> <end>`. `<end>` is unchanged from round 3. `<open>`
is now one of exactly three positions:

```
(?P<open>
   ^[ \t]*(?:[-*+#][ \t]+|[0-9]+[.)][ \t]+)?   # line start, maybe one marker
 | ["'`]                                       # one opening quote or backtick
)
```

- **line start**, with indentation, optionally after **one marker that abuts the
  slash** (`  - /brag`, `1. /brag`, `# /brag`, `    /brag`);
- **an opening quote or backtick** directly before the slash (`say "/brag"`,
  ``use `/brag` ``).
- A space or tab before the slash is **not** an opener any more. `cd /brag`,
  `then run /brag`, `Trigger: /brag.`, `[x](/brag)` are prose, and `- cd /brag`
  is prose too, because the marker branch requires the slash immediately after
  the marker - the marker cannot re-open the path hole.

**Decision on an in-prose mid-line mention: it is left exactly as written, on
purpose.** It is not rewritten, not deleted, and not silently folded into the
"0 bare left" line: the lint classifies it as `not-activation-position` and the
run prints the count. A prose mention therefore costs documentation accuracy
(the card says `/x`, pi registers `/skill:x`) and buys refusal of the false
positives `cd /brag` and `then run /brag`. That trade is the ticket's decision;
§6 lists what it costs on this machine.

then executed on each row:

## 3. `update-all.sh`: `PIPESTATUS`, with `pipefail` off

Six pipelines whose stage 0 decides the run now go through one wrapper:

```bash
run_logged() {
  local rc had_pipefail=0 had_errexit=0
  shopt -qo pipefail && had_pipefail=1
  case $- in *e*) had_errexit=1 ;; esac
  set +o pipefail
  set +e
  "$@" 2>&1 | tee -a "$LOG"
  rc=${PIPESTATUS[0]}
  [ "$had_pipefail" = 0 ] || set -o pipefail
  [ "$had_errexit" = 0 ] || set -e
  return "$rc"
}
```

Both options are cleared for the pipeline itself and restored after: with
`errexit` on, a failing stage 0 would kill the shell before `PIPESTATUS` could be
read, and the step's own `ERROR:` line would never reach the log. Converted:
`apply_skill_activation` (was already `PIPESTATUS`, now pipefail-independent),
`apply_skill_cap` (`skills-cap.py`, `skills-cap-check.py` - the reviewed
swallow), `generate_pi_agents`, `apply_pi_patches`, the compaction escape test
(`run_logged ... && tail -1 "$LOG" | grep -q '^PASS'`; the decision is grep's, and
`tail` cannot fail meaningfully). Left as plain pipelines, with the reason in the
file: `log()`'s own `echo | tee`, the checklist/manifest table printers,
`grep ... || echo "(none)"`, `wc -l | tr`, and the stale-run prune
`find | sort | tail | xargs rm` (empty input deletes nothing).

Proof (`bash ~/.agents/loop/it3-5-pipestatus-proof.sh`): a stub `python3` that
exits 3, sourcing the real `update-all.sh` and calling the real
`apply_skill_cap`, compared against `HEAD`'s pre-fix file:

| file | shell options | returned | own `ERROR` line printed |
|---|---|---|---|
| HEAD (old `\| tee \|\| rc=1`) | `set +o pipefail` | **0** - swallowed | no |
| HEAD (old) | `set -o pipefail` | 1 | yes |
| current | `set +o pipefail` | **1** | yes |
| current | `set -o pipefail` | 1 | yes |
| current | `set -euo pipefail` (a `run_jobs` child) | 1 | yes |
| HEAD | `set -euo pipefail` (a `run_jobs` child) | 1 | yes |

The first row is the hole: same failing step, exit 0, no message. The fix makes
the answer identical in all four option states.
