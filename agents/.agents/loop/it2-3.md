session; the measurement commands are in the report so the next iteration can
re-run them instead of trusting the prose.

## 2. The transform

`~/dotfiles/jcode/skills-cap.py` (new, 260 lines, stdlib + local `yaml`, no network).

* Roots: `~/.agents/skills`, `~/.pi/agent/skills`, plus the package trees
  `~/.pi/agent/npm/node_modules/*/skills` and `~/.pi/agent/git/github.com/*/*/skills`
  (npm and `git pull` overwrite those too — leaving them out would leave entries no
  sync ever re-caps). Deduped by realpath, so the `.pi/agent/skills` symlinks are
  not processed twice.
* It rewrites only the `description:` entry inside the frontmatter block, keeping
  the rest of the file byte-identical (verified: 30 tracked SKILL.md changed, 0
  with a changed body).
* Deterministic: pure function of the file text, no clock, no randomness, no
  network. Idempotent: a description under the cap is left untouched, and the
  rewritten form is itself a fixed point (proved in §3).
* Exit 1 if any output is still over the cap, if any extracted routing term is
  missing from its output, or if an output would be empty (pi drops a skill with an
  empty description — that would delete the entry, not shorten it).

Shape of a rewritten entry:

```
before 527 B  Configure and troubleshoot Superwhisper dictation on Linux through its CLI.
              Use when the user asks to change or inspect Superwhisper: processing mode
              (Offline, Offline Lite, Cloud), language, tone, microphone, … Triggers:
              superwhisper, dictation, speech to text, push to talk, voice typing.
after  159 B  Configure and troubleshoot Superwhisper dictation on Linux through its CLI.
              Use when: change, inspect Superwhisper, superwhisper, dictation, speech to
              text, push to talk, voice typing, CLI.
```

## 3. Durability: the sync cannot complete without it

`apply_skill_cap` (update-all.sh:467) runs after `apply_overlays` and before the
manifest, calls the transform then the check, logs both, and on non-zero does
`checklist_add fail` — and `main` already does `if grep -q '^fail' …; then rc=1`,
so the run cannot exit 0 with an uncapped catalogue.

Evidence, not intent:

```
$ git -C ~/dotfiles checkout -- agents/.agents/skills     # upstream wipe
$ source update-all.sh; apply_overlays; apply_skill_cap   # the sync's own path
[2026-11-13T09:39:39Z] === skill catalogue cap ===
skills-cap: cap 270 B, 145 skills with descriptions, description bytes 29844 -> 25413 (-4431), 31 rewritten
skills-cap-check: 145 descriptions, cap 270 B (escaped, as loaded), largest codebase-design at 270 B
rehearsal rc=0
```

* **Wipe → re-sync → transform reproduces the tree exactly.** All 137 installed
  descriptions byte-identical before and after the wipe+resync cycle, twice over,
  and equal to `transform(upstream)` for all 98 catalogue entries (0 deviations).
* **The gate actually fires.** With the cap temporarily set to 210 B, the same
  rehearsal returned `rehearsal rc=1`, `ERROR: skill catalogue cap failed;
  descriptions are not capped` — the run aborts rather than shipping a bad tree.
* **Check after a bare wipe** (no transform): `37 over cap` including
  `tiger-style 686 B > 270 B`, exit 1.

Note two of the 98 entries (`superwhisper`, `cua-driver`) are symlinks into app
installs (`~/.local/share/superwhisper/app/…`, `~/.cua-driver/…`). `git checkout`
restores the symlink, not the target, so the rehearsal had to restore those two by
hand; an app upgrade does the same thing. That is the one hole the design cannot
close mechanically — the check converts it into a failed sync, and the fix is one
`update-all.sh` run.

## 4. The trap: which words are the routing words

A description is two different things: what the skill does, and what a user types
to summon it. Cutting the second makes the saving worthless, so the transform
keeps a term set explicitly and drops only prose:

**Kept verbatim**
1. the trigger clause items — text after `Use when / use only when / use this skill
   when / use for / use to / use on / use before / use after / Triggers: / trigger
   when / also triggers / invoke [with]`. Phrasings were enumerated from the corpus
   (57 × "use when", 20 × "use for", 8 × triggers, 5 × invoke, 3 × "use before"),
   because a phrasing left out is a clause silently discarded as prose — exactly
   what happened to `code-review` ("Use to review a branch, PR or WIP change") and
   `herdr` ("Use only when …") in my first two passes;
2. every quoted phrase, every backticked term, every slash command;
3. proper nouns (ALLCAPS, camelCase, digits, dotted names: `HERDR_ENV`,
   `CLAUDE.md`, `TigerBeetle`, `/caveman`).
4. the scope enumeration *after a colon inside a trigger clause* is dropped
   (`Use when the user asks to change X: processing mode, language, tone, …` is a
   list of settings, not a way to summon the skill).

**Dropped**: sentences with no trigger clause, and terms whose words are already
inside a longer kept term (a substring costs bytes and buys no matching surface —
the words are still in the text).

**Kept as a scope line**: the first sentence (identity) at whatever width still
fits; a skill whose trigger clause is the whole description gets no scope line.

### Proof per skill

438 terms across the 98 catalogue entries, 0 lost:

```
| skill                | before | after | terms kept | lost |
| tiger-style          |    686 |   248 |     12     |   0  |
| superwhisper         |    527 |   159 |      7     |   0  |
| cua-driver           |    431 |   178 |     10     |   0  |
| openhilclimb         |    341 |   266 |      9     |   0  |
| learned              |    385 |   216 |      4     |   0  |
| codebase-design      |    270 |   270 |      7     |   0  |
| herdr                |    328 |   192 |      8     |   0  |
| intent-interview     |    330 |   233 |      8     |   0  |
   … all 98 rows in ~/.agents/loop/it2-3-terms.tsv (before_B, after_B, terms, lost)
```

`learned` is the case that proves the rule matters: its description has no quotes
and no Proper nouns, so a token-only extractor drops "working the dag/stagehand PR
pipeline" and "driving multiple cmd/opencode agents through herdr" — an earlier
pass of mine did exactly that and the check passed, because the check was using the
same extractor. The trigger-clause rule keeps it: `learned` after = `The
dag/stagehand PR-pipeline playbook. Use when: working the dag/stagehand PR
pipeline, driving multiple cmd/opencode agents through herdr, a PR must go
adversarial-review -> whiteboard -> refiner -> merge.`

### Where a lower cap would start costing words

The floor per skill is its trigger vocabulary. `270 B` is the smallest round step
above the measured maximum (`openhilclimb`, 266 B). Below it:

| cap | skills that lose routing words | what they drop |
|---|---|---|
| 250 | openhilclimb (266 B) | `improve eval score` |
| 225 | openhilclimb | `hillclimb`, `optimize agent`, `improve eval score` |
| 200 | openhilclimb; tiger-style (205 B) | `keeping only improvements that raise the held-out test score`, `improve eval score`; `TigerBeetle` |
| 175 | + codebase-design (195 B); learned (189 B) | `another skill needs the deep-module vocabulary`; `a PR must go adversarial-review -> whiteboard -> refiner -> merge` |
| 150 | + intent-interview (174 B); docker-agent-command-code (172 B); wizard (157 B); cua-driver (152 B) | `names a goal without a shape`; `hits \`unsupported harness.type "command-code"\``; `cutover`; `MCP` |

So the hoped-for 200 B cap would have cost trigger words on 2 skills (4 at 175, 8
at 150). **Cap set to 270 B, where the loss is zero.** The saving is 4,751 B rather
than the hoped 6,204 B — that gap *is* the routing vocabulary of the skills whose
descriptions are pure trigger lists.

## 5. The check

`~/dotfiles/jcode/skills-cap-check.py` (new, independent of the transform's logic;
it reads the cap from `skills-cap.py --print-cap` and re-measures from disk).

Fails on: any description over the cap (measured on the **escaped** bytes, which is
what the prompt carries — `"` costs 6 bytes as `&quot;`); any missing/empty
description (pi would drop that skill); any term recorded in
`~/.jcode/state/skill-catalogue-terms.tsv` that no longer appears in the installed
description. `--root DIR` (repeatable) runs it against a copy.

Proof it fails on a copy:

```
$ cp -a ~/.agents/skills /tmp/cap/copy && python3 -c '…set flow description to 300 x’s…'
$ skills-cap-check.py --root /tmp/cap/copy

$ skills-cap-check.py --root /tmp/cap/copy2
```

## 7. What this does not do, and the risks

* **200 B was not achievable losslessly.** Reported above per skill; the cap is
  270 B because of `openhilclimb` (266 B) and `tiger-style` (205 B). A future
  extraction that can compress a long *phrase* to its key words (rather than
  keeping whole clause items) is what would make 150-200 B possible without loss;
  that is a different, riskier transform and I did not do it.
* **Two entries live outside every synced tree** (`superwhisper`, `cua-driver`
  symlinks into app installs). The cap holds until the app upgrades its asset; the
  check then fails the sync instead of losing the bytes silently.
* **The term ledger is derived from the text the transform receives**, i.e. from
  upstream. If upstream rewrites a description, the recorded terms change with it
  — correct (upstream's words are the routing words), but it means the ledger is
  not an independent oracle for "what upstream said last year". The guard catches
  the case that matters: descriptions on disk that the transform did not produce.
* **NOT done**: `~/.agents/AGENTS.md`, `~/.pi/agent/AGENTS.md` untouched, as
  required. Pack 4's family collapse (53 entries / 21.8 KB) is untouched — this
  ticket only removes description prose.
* Changes are live on disk and **uncommitted** in `~/dotfiles` (`jcode/update-all.sh`,
  `jcode/skills-cap.py`, `jcode/skills-cap-check.py`, plus 30 rewritten tracked
  SKILL.md). A commit is a separate decision.
* `~/.jcode/state/skill-catalogue-terms.tsv` is new durable state (provenance-style
  ledger, same place as `upstream-sources`).
