# /home/prm — machine orientation
This is a home directory, not a repository. The rules every session follows
live in `/home/prm/.agents/AGENTS.md` — read them there, they are not repeated
here. Below is only the layout and the traps that cost a session time.

## Who owns what

- `/home/prm/.agents` → `/home/prm/dotfiles/agents/.agents` (symlink). Canonical,
  harness-neutral home: `AGENTS.md` (rules), `skills/`, `references/`,
  `LEDGER.md` (loop router only), `loop/` (per-ticket reports).
- `/home/prm/dotfiles` — git repo, source of truth (stow-style: live paths are
  symlinks into it). Owns the `.agents` tree, `jcode/` (updater, skills audit),
  `skills-overlay/`.
- `/home/prm/.pi/agent` — pi's agent dir. Owns pi state: `settings.json`,
  `mcp.json`, `models.json`, `auth.json`, `trust.json`, `extensions/`,
  `sessions/`, and generated mirrors `skills/` → `/home/prm/.agents/skills`,
  `npm/` and `git/` (installed pi packages).
- `/home/prm/.commandcode` — Command Code's home: `settings.json`, `hooks/`,
  `mods/`, `sessions/`, `skills/` (83 symlinks into `/home/prm/.agents/skills`).
- `/home/prm/.jcode` — jcode harness, upstream-managed fork. Read-only except
  through its updater.

## Skills are the workflow layer

- Entry point for repository work is the `flow` skill (`/flow`): it names one
  skill per phase. Questions, research and chat do not need it.
- Do not re-derive the tree by reading the 126 `SKILL.md` files. Read
  `/home/prm/.agents/skills/README.md`: one generated table of every skill,
  its upstream and commit.

## Guard rules that bite

- Spawn agents interactive only: `hc run --bg --name <n> pi`, then `hc send`
  and `hc read`. One-shot `pi -p`, `claude -p`, `codex exec` through hc/herdr
  is blocked by `/home/prm/.pi/agent/extensions/herdr-interactive-only.ts`.
  Restated because a hook enforces it, not memory.
- Everything else: `/home/prm/.agents/AGENTS.md`.

## App-managed — do not edit

- `/home/prm/.agents/skills/` — regenerated by
  `/home/prm/.jcode/bin/update-all.sh`. Fixes go in `<skill>.sh` files under
  `/home/prm/dotfiles/skills-overlay/` (or `skills-overlay/host/` for
  `/home/prm/.pi/agent/skills`); the updater re-applies them.
- `/home/prm/.agents/LEDGER.md` — only the loop router writes it.
- `/home/prm/.pi/agent/npm`, `/home/prm/.pi/agent/git`,
  `/home/prm/.pi/agent/sessions`, `/home/prm/.commandcode/sessions`,
  `/home/prm/.commandcode/projects`, `/home/prm/.commandcode/history.jsonl`
  — app state, rewritten by pi and cmd.
- `/home/prm/.jcode` — only via its updater.

## Facts that cost a day to learn

1. `/home/prm/.agents` is a symlink into `/home/prm/dotfiles`, so editing it is
   a dotfiles commit; the real status is `git -C /home/prm/dotfiles status`.
2. `bash /home/prm/.jcode/bin/update-all.sh --dry-run` is the one command that
   reconciles skills, overlays and harness configs; log at
   `/home/prm/.jcode/logs/update-all.log`.
3. No `graft` here; `rg` and `fd` come from `/home/prm/.pi/agent/bin` on PATH.
